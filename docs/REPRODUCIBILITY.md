# Reproduction guide

**Efficient estimation and the cost of complete-case coarsening under monotone sequential MAR**
Keivan Bolouri — corrected analysis, 10 September 2026

This package contains the corrected manuscript, source, simulation code, full replicate results, and figure/table generators. The manuscript uses only results regenerated by this version of the code. The earlier uploaded CSVs and numerical tables are superseded, not combined with the corrected results.

## Files

- `paper/paper.pdf`: revised manuscript for author review and initial submission.
- `paper/paper.tex`: main editable source; it includes `simulation.tex` and `appendix_d.tex`.
- `paper/figures/`: the figures used in the manuscript.
- `code/dgp.py`: the Gaussian stress design and the prospective bounded-propensity design, plus oracle nuisance functions.
- `code/crossfit.py`: observed-data estimators and a separate full-data benchmark.
- `code/run_studies.py`: the full estimated-nuisance simulation grid.
- `code/oracle_sim.py`: primary oracle experiment and paired Monte Carlo bootstrap.
- `code/quadrature.py`: deterministic variance identity at two numerical resolutions.
- `code/sensitivity_check.py`: calibrated response-mechanism experiments.
- `code/gen_appendix.py`: all numerical tables and simulation-result prose.
- `code/make_figures.py`: plots from the same result files as the tables.
- `code/verify_results.py`: validates replicate counts, summaries, interval endpoints, and configuration coverage.
- `results/`: JSON summaries and exact configurations; `results/replicates/` contains all individual estimates and standard errors.
- `tests/test_estimators.py`: regression tests for the corrected implementation.
- `docs/CHANGES.md`: scientific, numerical, and implementation changes.
- `docs/VALIDATION.md`: completed checks and remaining limits of the evidence.

## Environment

The recorded run used Python 3.12.14; use Python 3.12 to match it. `requirements.txt` pins the versions used for this run; `environment.json` records the actual Python/platform/package versions. Numerical-library thread counts are set to one in the run driver so parallel workers do not create additional thread pools. Reproduction across numerical-library or platform versions may differ in the final floating-point digits.

From the package root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the virtual environment using its `Scripts` directory instead. No network access or external dataset is needed after dependency installation.

## Regenerate all simulations

Run from the package root. The output paths resolve relative to the code location, not the current shell directory.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest discover -s tests -v
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python code/oracle_sim.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python code/quadrature.py
python code/sensitivity_check.py --workers 2
python code/run_studies.py --workers 6
python code/verify_results.py
python code/gen_appendix.py
python code/make_figures.py
```

The `OPENBLAS_NUM_THREADS=1` syntax above is for POSIX shells; set the equivalent environment variables before running commands in other shells. The two parallel drivers set thread limits internally. Adjust `--workers` to available CPU capacity. The full estimated-nuisance study uses 14,500 simulated samples, the primary oracle study uses 4,000, and the sensitivity study uses 30,000. Runtime depends on hardware.

`run_studies.py --resume` skips configurations with a completed JSON result. Use resume only within an unchanged code/configuration run. For a new analysis, use a clean results directory. A convergence warning or nonfinite estimate stops a configuration; a completed JSON file is written only after all replicates succeed. A partial CSV without its JSON summary is not a completed result and is not used by the table generator. Missing configurations cause generation/verification to fail.

A small implementation smoke run is available with `python code/run_studies.py --pilot 10`; it writes into `results/pilot/` and is never used in the manuscript. It does not replace the full study.

To run one configuration, for example:

```bash
python code/crossfit.py --design bounded --n 2500 --reps 1000 --tag bounded_n2500
python code/crossfit.py --design stress --n 2500 --reps 1000 --oracle-response --tag stress_or2500
```

## Random-number streams

The full grid and all flag settings are recorded in `results/run_manifest.json`.

For estimated nuisances, every replicate uses:

```python
numpy.random.default_rng(numpy.random.SeedSequence(
    [20260910, design_id, scenario_id, n, replicate_1based]
))
```

Design indices are 0 for the Gaussian stress design and 1 for the bounded design. Scenario indices are 0 for common validity and 1 for sequential MAR only. A replicate draws full data, response indicators, and then a random permutation assigning the five folds. The oracle flags deliberately do not change the stream, so diagnostic comparisons at the same design/scenario/sample size are paired. Replicate numbering starts at one. Streams are independent of job scheduling and the total number of requested replicates.

The primary oracle study uses `SeedSequence([seed, replicate_1based])`, with seeds 20260910 and 20260911 for the two scenarios. The 10,000-resample paired variance bootstrap uses seed 20261009. Sensitivity scenarios `eff0`, `eff1`, `eff2` use seeds 20261910, 20262010, 20262110; `ident0`, `ident1`, `ident2` use 20262910, 20263010, 20263110. Each uses the same two-component SeedSequence construction. Sensitivity bootstrap seeds are their scenario seeds plus 99. All are explicit in the JSON records.

## Estimators and oracle flags

The incomplete-data estimator accepts unavailable confounders as `NaN`. It reads `L1` only where `R1=1`, and `L2` only where `R2=1`. Its `L2` spline knots use complete training records. The full-data benchmark is a separate function and chooses its own spline basis from all full training records. A validation record is excluded from every nuisance fit and basis transformation used for that record.

Cubic B-splines use six empirical quantile knots, degree three, and `include_bias=False`. Models include intercepts. Designs are saturated in the corresponding binary variables, as specified in Appendix D. Logistic regressions use `C=1` and `max_iter=2000`; ridge regressions use `alpha=0.001`. Fitted treatment probabilities are truncated to `[0.01,0.99]`, and fitted response probabilities to `[0.01,1]`. Hyperparameters are fixed. There is no inner cross-fitting within an outer training fold.

- `--oracle-causal`: true treatment and outcome functions everywhere `G` is evaluated, including projection training.
- `--oracle-response`: true stage-one, stage-two, and coarsened response probabilities in training weights, the training pseudo-outcome, and validation augmentation.
- `--oracle-q`: true projection functions; this requires `--oracle-causal`. For the coarsened diagnostic, it uses the complete-case projection `Q0cc`. Outside common validity, even this all-oracle coarsened procedure is biased.

Oracle probabilities are untruncated. The primary `oracle_sim.py` also reports a coarsened version using the full-law `Q0`. Both coarsened oracle versions have the same population mean when true `G` and `rho` are used; finite-sample variances and coverage can differ. Estimated coarsened causal functions need not target full-law functions when CCMAR fails.

## Output and statistical definitions

CSV files contain one row per replicate and estimator, with full-precision estimates, standard errors, interval endpoints, and a coverage indicator. Monte Carlo coverage is the mean of `covered`. Bias is mean estimate minus the true ATE; empirical SD uses `ddof=1`; RMSE uses the mean squared error around the ATE. Mean SE averages within-sample influence-function standard errors. Bias MCSE is empirical SD divided by the square root of the replicate count. Coverage MCSE is `sqrt(coverage*(1-coverage)/reps)`.

Variance reduction is `100*(1-var(seq, ddof=1)/var(cc, ddof=1))`. It is not an MSE reduction. The paired bootstrap resamples entire replicate pairs and recomputes both centered variances. Its interval quantifies Monte Carlo uncertainty in the variance comparison, not uncertainty in an individual study's treatment effect.

The sensitivity intercepts solve the population complete-record-share equation using deterministic quadrature. Population targets and empirical response shares are both stored and distinguished in the manuscript.

## Scope

The bounded design satisfies uniform treatment positivity and has a known ATE of 0.15. The Gaussian design has a finite oracle variance but fails uniform treatment positivity and exhibits substantial interval undercoverage with the specified learner. The software corrections do not establish reliable intervals in that stress design. The manuscript reports these limitations explicitly; no unsupported bootstrap repair, universal finite-sample advantage, or demonstrated nuisance convergence rate is claimed.
